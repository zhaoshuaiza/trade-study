# 昆虫系统——可复刻的趋势跟踪配方

## R — 原文

> “对于趋势跟踪者而言，我们不怕上涨也不怕下跌，甚至我们连整理都不怕。”

—— 第六章 系统之路 · 昆虫系统

> “分散投资是一种资金管理工具，而不是一种风险防范工具。”
> “分散投资可以作为资金波动幅度的‘减震器’，从而规避大面积资金回撤。”

—— 第六章 / 第七章 资金管理

> “资金管理采用等额投资法。单从资金管理上来思考的话，那么赢冲输缩的下注策略具有明显的优势；
> 但从趋势跟踪系统的特点上来思考的话，趋势行情通常产生于整理行情过后，
> 也就是说连续几次亏损后才能出现大利润。”
> “最好的办法就是等额投资法。事实上，本系统在设计上已经体现了赢冲输缩的思维方式。”

—— 第六章 系统之路 · 昆虫系统（原书第 182 页）

> “我们怕的就是那种‘恰到好处’的整理！”

—— 同上

## I — 自述

书名里的"昆虫"来自第二章的恐龙对比：恐龙极致地适应了当时的环境而称霸，环境一变就灭绝；
昆虫什么都没精通，却活了下来。作者要的就是这种**不依赖任何一次判断正确**的生存结构。

这是全书唯一一处给出**完整可落地配置**的地方，四个要素缺一不可：
1. **分散**：跨品种、跨市场地持有多个标的，让任何一次判断都不决定生死。
2. **趋势跟踪**：用"一定程度的反向波动即视为趋势改变"的机械规则进出，不做预测。
3. **等额投资**：每份投入相同的资金额度，而不是对看好的多投。
4. **等额的资金管理**（这是作者权衡后的结论，不是默认假设）：他比较过两种思路——
   单从资金管理看，"赢冲输缩"有优势；但趋势跟踪的大利润出现在**连续几次亏损之后**，
   纯按"赢冲"会让真正获利的那一次仓位最小。为避免这个错位，他最终选择**等额投资法**，
   并说明本系统的设计本身已经体现了加码/缩减的思维（分散 + 顺势 = 盈利时自然放大）。

它的深层逻辑是：趋势利润集中在极少数几次大行情里，而这些大行情**事先无法识别**。
既然无法识别，就不能重仓押注，只能广撒网、等额、 Mechanical 地一路跟下来。
与本书其他部分的关系是——它是"一致性""必須志同道合的执行""不要叠加"这些原则的唯一范例。

## A1 — 书中案例

**c06：2006 年期货账户两个月从 17 万到 60 万**
- 遇到什么：作者把这套分散趋势跟踪的做法放到期货上执行。
- 怎么用：多品种分散持有 + 机械的趋势信号进出 + 等额资金分配。
- 结论：利润来自少数品种的大趋势覆盖其余品种的连续小亏；中间不需要对某个品种看得更准。
- 实际结果：两个月 17 万 → 60 万。作者同时强调，这恰恰印证了"泰山不让土壤"的分散思路，
  而不是选品能力。

**恐龙与昆虫的对比（第二章 · 恐龙效应）**
- 作者用以说明为何选"昆虫"范式：恐龙因极端适应特定环境而灭绝，昆虫因不挑环境而存活。
- 结论：系统的目标不是在某一段行情里表现最优，而是在任何一段行情里都活下来。

## A2 — 何时触发

用户会在这些情境里遇到它：
1. 直接要一套能照着做的交易系统，而不是一堆原则。
2. 已经认同趋势跟踪，但不知道具体怎么搭、怎么分钱。
3. 纠结"每笔该买多少"、"要不要对看好的加仓"。
4. 想知道"需要选股能力吗"、"要不要盯很多品种"。

语言信号：
- 中文：「给我一套能直接用的系统」「趋势跟踪具体怎么做」「每笔仓位怎么定」
  「资金怎么分配到多个品种」「需要选股吗」「是不是要好几个账户/品种一起做」。
- 英文：*"give me a working trading system" "trend following system how to build" "position sizing per trade" "how to allocate capital across markets"*

与相邻能力的区分：
- 用户问**该不该改参数/加过滤** → 那是优化与组合陷阱。
- 用户问**风控由哪两件事构成** → 那是风险防范两点。
- 用户问**某笔亏损该怎么看待** → 那是成本观。
- 本条是唯一一条**输出一份配置**的能力；其他都是判断与解释。

## E — 可执行步骤

1. **定标的池**：选一批分散的标的（不同行业/不同品种），数量以"任何一个标的的失败都不足以改变年度结果"为准。
   完成标准：能说出自己的分散原则，且不是单纯的同板块多只票。
2. **定趋势规则**：用一句话写出进出的机械条件——采用"达到一定幅度的反向波动即视为趋势改变"。
   完成标准：规则里**没有**"我觉得""应该是""如果基本面配合"这类主观词。
3. **定单份额度**：先确定单笔能接受的最大亏损（落在"输得起"的范围内），
   再由止损幅度反推出每份的资金额度，并且**每份金额必须相同**。
   完成标准：每份额度一致，且"单份 × 止损幅度"是用户事先承认能承受的数字。
4. **定加码规则（默认等额）**：先按作者的结论用**等额**；若一定要加码/缩减，必须写出触发条件，
   并特别检查一件事——**别让获利的那一次变成仓位最小的一次**（这正是他放弃机械赢冲输缩的原因）。
   完成标准：加/减都有事先规则；或者明确回答"我就用等额，不加减"。
5. **承诺周期**：写下"至少跑完一轮完整的信号序列，中途不改规则"。
   完成标准：期限已写明并可执行。

判停：若用户没有止损、也没有资金分配，只想问"买哪个" → 停止，这不是本能力的问题；
先把"输得起的上限"定出来。

## B — 边界

- **不要**推荐具体标的、品种或所谓"优质 pool"。本能力给的是结构，不是清单。
- **不要**因为追求分散而建议买一大堆高度相关的东西（同一板块的多只票不算分散）。
- **不要**给出具体的份数或百分比数字。额度必须由用户自己的"输得起"推导。
- **不适用**：日内/超短、打板、事件驱动；以及要 predicting 哪一波会涨。
- **A 股与可转债适配（重要）**：作者在期货双向市场验证这套配方，直接照搬会出问题——
  - 只能做多，空头那一半没有，下跌段无法获利，耐心要求更高；
  - 股票有 ±10%、一字板，信号触发时可能**无法成交**，趋势规则要预留不可成交的处理；
  - 可转债虽 T+0、无涨跌停且 ±20%，但**强赎条款是独立于走势的外生离场信号**——
    触发强赎时，价格可以被按面值附近赎回，与技术形态无关，**必须单独检查，不能被趋势规则覆盖**；
  - 作者本人主要在期货上验证，对股票/转债的适用性数据不足，宜小额度、多周期地观察后再放大。

## 注

作者把分散定位为"资金管理工具"而非"风险控制"，两者不要混淆（见风险防范两点）。
