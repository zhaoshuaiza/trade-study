# 数据维护规则（交易学习库 SOP）

> 本文件是 **交易学习库**（`E:\Work Buddy\交易学习`，Obsidian vault + git）的统一数据维护标准。
> 所有账号 / AI 每次维护都必须遵守；每日收尾按第七节逐项勾选。
> 最后更新：2026-10-25。单一事实源：本文件。交接板与记忆只引用本文件，不另起一套。

## 〇、适用范围与单一事实源
- 适用对象：库内所有 Markdown（`wiki/`、`raw/`、`books/`、根目录交接板）、`.obsidian` 配置、记忆文件（`.workbuddy/memory/`）。
- 单一事实源：本文件。任何"通用操作规范 / 交接板 / 记忆"中的维护规则，以本文件为准；不一致时以本文件更新之。
- 已有配套：每日闭环检查另见 `wiki/market/闭环检查清单.md`（本文件第七节是它的维护侧补充，二处互相引用，不重复造轮子）。

## 一、文件操作铁律（4 条 · 通用操作规范）
1. **不改名**：任何已有文件绝不重命名，防止 Obsidian 双链 / 反向链接失效。
2. **保留 frontmatter 与标签**：编辑 `.md` 时原样保留头部 `---` 块与文内 `#标签`，只改正文内容。
3. **新建笔记归位**：新文件统一存入 `01_新建笔记/`（该目录首次需要时创建，不污染库根）。
4. **大改前先备份**：凡需覆盖大量内容的文件，先在同目录复制为 `[原名]_备份_YYYYMMDD.md`（用当日日期，如 `_备份_20261025.md`），再动笔。

## 二、版本控制闭环（防"以为提交实则没提交"）
5. **编辑后立即提交**：每次改完 `git add <path> && git commit -m "..."`，**不依赖 Obsidian Git 自动提交**（实测其自动提交会跳过 / 丢失，详见 `wiki/meta/OCR与编译踩坑记录.md`）。
6. **提交后验证入库**：`git show HEAD:<path> | grep <关键词>` 确认内容真的进了版本库。
7. **记忆与交接板必须入库**：`.workbuddy/memory/*`、`00_今日交接.md` 改动后必须提交，否则换机 / 换账号丢上下文。
8. **关机前确认飞牛同步完成**：避免本地提交未同步，另一台机器拿不到。

## 三、OCR / 蒸馏闭环（OCR 完成 ≠ 收口完成）
9. **OCR 完成 ≠ 收口完成**：必须走完 `consolidate 合并分片 → 蒸馏判据 → 更新 sources 页状态 → 提交` 四步才算闭环。
10. **sources 页状态必须与实际一致**：OCR 进度 json 显示 `failed 0` 不代表工作完成；须肉眼核对章节是否齐全（如黄金宝典第六章），并把 `·待OCR.md` 占位页改为"已 OCR / 已蒸馏"。
11. **蒸馏产物必须建索引 / 反链**：`01_新建笔记/` 新建的判据笔记要被 `wiki/hot.md`、`wiki/syntheses/` 合成页或索引引用，否则是孤儿页。
12. **lint 校验闭环**：每次大改后跑 `python lint_vault.py`，确保死链只剩已知模板占位；新出现的死链必须修复或登记。

## 四、双链与结构闭环
13. **结构性改动后跑链接检查**：改名 / 移动 / 合并文件后，必须 `lint_vault.py` 或手动核查双链是否失效（改名已被规则 1 禁止，但分片合并、目录整理仍可能移动文件）。
14. **备份验证**：覆盖前确认 `_备份_YYYYMMDD.md` 已存在且可读，再动原文。

## 五、回滚 / 恢复铁律（来自 workspace 记忆，跨账号通用）
15. **恢复前先看锚点**：任何"恢复 / 回滚 / 改回"前，先对照 `git reflog` / `git log` 时间线，搞清要恢复的是哪一段。
16. **先问再动**：对照后必须用 AskUserQuestion 问用户"是否全部恢复 / 恢复到哪"，确认范围后再动手，**不得擅自 reset / 删除**。
17. **破坏性操作先备份**：用 `.bak_YYYYMMDD_HHMM` 后缀原样保留，不删数据。
18. **改 `.obsidian` 配置**：① 尽量先关 Obsidian；② 改完**读回验证**（不能只信一次报告）；③ 验证通过立刻提交（防内存重写回退）。

## 六、查资料纪律
19. **查外部资料前先写备注**：任何对外查资料 / 抓取前，先在文档写 `> [AI 备注]` 并等用户确认，再继续。

## 七、每日执行清单（收尾必跑，逐项勾选）
- [ ] 当日所有编辑已 `git add + commit`，并对关键文件 `git show HEAD:<path> | grep` 验证入库
- [ ] `.workbuddy/memory/*` 与 `00_今日交接.md` 已提交
- [ ] 新建笔记已入 `01_新建笔记/` 且已建索引 / 反链
- [ ] 若有 OCR / 蒸馏：已 consolidate + 更新 sources 状态 + lint + 提交
- [ ] `python lint_vault.py` 通过（死链仅已知占位）
- [ ] 飞牛同步确认完成后再关机
- 配套：与 `wiki/market/闭环检查清单.md` 一并核对

## 九、备份命名统一约定
- **内容大改备份（防改坏）**：`[原名]_备份_YYYYMMDD.md`，同目录，当日日期。
