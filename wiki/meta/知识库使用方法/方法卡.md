## 一、收集 —— 把外面的东西变成库里的素材

| | |
|---|---|
| **做什么** | ① 判定归属 → ② 落 `raw/` 对应入口 → ③ 保留元信息 → ④ IMA 库只登记指针 |
| **输入** | 一篇网页/公众号文章、一条调研纪要、一本书、一段聊天里得到的结论 |
| **输出** | `raw/` 里带 frontmatter 的素材文件（有来源、有链接、有日期）；或一条「IMA 指针」登记；或一张「已分流/不收」登记 |

**判定归属（一句话）**：能不能落成「看盘时用得上的动作」？
能 → 本库；不能 → `hedge` 库；工具书/无关 → 登记后不入库。

**收录标准（宁缺勿滥）**：

| ✅ 收 | ❌ 不收 |
|---|---|
| 有完整论证的深度长文 | 营销软文、无观点资讯 |
| 讲清一个方法论的教程 | 标题党、碎片化观点 |
| 一手经验总结 | 纯转述的二手内容 |
| 有数据支撑的分析 | 没有论据的情绪化判断 |

> 判断标准：**这条信息以后遇到真实问题时，会不会回来看这一页？**

**关键纪律**：

1. **IMA 五库不搬运** —— 体量 5.6万 / 3万 / 5539 / 2539 / 1853 条，照搬会撑爆本地库。只登记「库名 + 检索关键词 + 命中条目标题」，用的时候现查。
2. **网页剪藏必须保留原文链接与时间**（Obsidian Web Clipper，目标目录 `raw/articles/`）。
3. **收件箱不过夜** —— 每周清一次，每次只处理 10 条。

## 二、检索 —— 先查库，再问人

| | |
|---|---|
| **做什么** | 按固定顺序分层查；查到给出处；查不到明说 |
| **输入** | 一个具体问题（「止损该设多少」「唐朝怎么看茅台」） |
| **输出** | 带出处的答案清单（wiki 页面名 / raw 路径 / IMA 条目标题）；或一句明确的「知识库中没有相关内容」 |

**检索顺序（不许跳步）**：

```
1. wiki/hot.md          最近在搞什么，先看这个
2. wiki/index.md        总索引的「先看这个」表
3. 对应子类索引          concepts / syntheses / …
4. 具体页面             只读真正相关的
5. raw/ 全文 grep       文件名 + 正文
6. IMA 库按主题选库      见表〇，一次只查一个库
```

**纪律**：

- 查不到就明说「库里没有」，**不许用模型训练知识冒充库内答案**。
- IMA 检索先收窄再读正文，不要把整库拖下来；跨库要分别查、分别说明出处。
- 答案必须带出处，格式 `（依据 [[页面名]]）`。

## 三、复用 —— 让查到的东西变成动作

| | |
|---|---|
| **做什么** | 把素材蒸馏成 wiki 页面，落成「动词 + 可验证的触发条件」，挂双链，更新索引 |
| **输入** | `raw/` 素材 + IMA 检索结果 + 你的真实问题 |
| **输出** | 新页面（八类之一）或对已有页的增量更新 + index/hot/log 更新 + git commit |

**沉淀标准**：

> 这条信息以后遇到真实问题时，会不会回来看这一页？
> 会 → 沉淀进 `wiki/`；不会 → 留在来源层，不进知识层。

**三条硬规矩**（详见 CLAUDE.md）：

1. **参数原封不动** —— 原书的周期、比例、阈值原样引用并标出处；要改造必须单列「原值 → 建议值 + 理由」。
2. **冲突要暴露** —— 体系结论不一致时建 `comparisons/` 页写清「什么时候用哪套」，不抹平、不选边站，取舍由你拍板。
3. **不给投资建议** —— 不写具体标的推荐、买卖点、收益承诺。

## 四、节奏

| 频率 | 动作 |
|---|---|
| **每次遇到问题** | 先检索再提问（30 秒规则：先查库，再问 AI） |
| **每周** | 清 `raw/` 收件箱：每次 ≤10 条，判「蒸馏 / 留源 / 分流 / 丢弃」 |
| **每两周** | lint 体检：孤立页、死链、索引漂移、参数被改、结论冲突未处理 |

---

## 五、红线（违反任何一条，这个库就废了）

1. **不移动、不重命名已有文件** —— 双链一断，知识层就散了。
2. `wiki/` 里只放蒸馏成品，原料永远在 `raw/` 或源层。
3. 查不到就说没有，不编。
4. 参数不许「优化」。
