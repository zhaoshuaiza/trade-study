# 知识库使用方法 · 常见问题处理

> 配套：[[方法卡]] · [[笔记模板]]

---

## Q1：找不到旧笔记了，怎么办？

**先分清：是真没有，还是没检索到。** 八成是后者。

### 按这个顺序再找一遍

1. **`wiki/index.md` 的「先看这个」表** —— 大多数常用页都登记在这
2. **Obsidian 全局搜索**，换 3 种说法搜：
   - 中文俗称 ↔ 术语（「割肉」↔「止损」↔「平仓」↔ stop loss）
   - **参数数字**（「2%」「20 日」「130%」——数字最不容易忘，也最容易被同义词漏掉）
   - 英文名（ATR / N / redemption / premium）
3. **`raw/` 全文 grep** —— 可能还在素材层没蒸馏
4. **IMA 库** —— 按方法卡表〇选库，一次只查一个

### 还是找不到

- 去 [[questions/问答与纠错机制]] 登记一条「查无此记 + 你想找什么」——这是待补清单，不是失败记录
- 顺手建一页占位（`status: uncertain`，只写你记得的片段 + 来源待补）——**下次检索能命中它，比让它继续不存在强**

### 预防（比找回便宜）

| 动作 | 防什么 |
|---|---|
| 建页当天登记进 `index.md` | 索引漂移（建了页但找不到） |
| 模板 `source` 字段必填 | 过了两周忘了这东西哪来的 |
| 剪藏保留原网页标题 | 搜索时匹配不到原文用词 |
| 命名说人话（「强赎条款」不写「条款2」） | 自己三个月后看不懂 |

## Q2：笔记太多，一直不整理，怎么办？

**核心答案：不整理文件，只整理索引。**

这个库的价值在双链，不在文件夹。移动/重命名一个文件，所有指向它的 `[[]]` 全断——**整理一次的代价是制造一批死链**。

### 三条治理规则

1. **不重归类** —— 文件放在哪就留在哪。靠 frontmatter 的 `type` / `tags` 检索，不靠文件夹整理。
2. **收件箱每周清** —— `raw/` 每周处理一次，每次只判 10 条：蒸馏 / 留源 / 分流 / 丢弃。判不完就停下，下周继续，**不许攒着**。
3. **`hot.md` 管近期** —— 最近在搞什么写在 hot 页；超过一个月的沉淀进 `index.md`。hot 是工作台，index 是图书馆。

### 什么时候才真该动手

只有四种情况。别的时候觉得「乱」，是搜索问题，不是整理问题：

| 情况 | 动作 |
|---|---|
| lint 报死链 / 孤立页 / 索引漂移 | 按报告修，修完 git commit |
| 一页内容横跨两类（既是概念又是观点） | 拆页，旧页留双链指过去 |
| 两页结论冲突但没地方放 | 建 `comparisons/` 页承接，不删任何一边 |
| 参数和原书不一致 | 标「原值 → 建议值 + 理由」，或改回原值 |

### 反模式（最常见的三种死法）

- ❌ 「等哪天有空把整个库重新整理一遍再学」—— 整理是检索的副产品，不是学习的前置任务
- ❌ 为了整齐把旧笔记批量改名/搬家 —— 双链一断，知识层直接散架
- ❌ 收藏越来越多、蒸馏越来越少 —— **收集的完成标志是「进 wiki」，不是「进 raw」**

## Q3：能把笔记直接存进那五个 IMA 知识库吗？

**不能，也不需要。** 这五个库（长安投研 / A股证券 / 唐朝价值投资 / 电子书库 / 王阳明心学）全是**只读订阅库**，账号没有写入权限；而且它们合计 9 万多条，本就是「源」不是「知识层」。

正确的分工：**IMA 库负责查得到，本地库负责记得住、用得上。** 在 IMA 里检索到的东西，按模板登记成指针或蒸馏进 `wiki/`，而不是想办法搬进去。
