# 术语溯源：三分类与核实流程

> ⭐⭐⭐ **本库最实用的防错机制。**
> 起因：2026-10-14 一小时内查出**三处出处标注错误**，
> 其中两处是「声称有理论出处，实际源书 0 命中」。
>
> 📌 **本库所有概念页的「理论出处」字段，都应能用本流程验证。**

---

## 一、⭐ 术语来源三分类

| 类型 | 定义 | 证据要求 | ⭐ 使用原则 |
|---|---|---|---|
| ⭐ **A 类：源书定义** | 正式出版物里有明确定义/专章 | 源书正文可定位 | 可深追、有体系、可查专章 |
| ⭐ **B 类：手记转述** | 手记引用/转述源书概念 | ⚠️ **须核对源书原话** | ⚠️ 转述可能走样，须纠错 |
| ⭐ **C 类：手记自创** | 源书 0 命中，只有手记在用 | 手记多本书重复出现 | ⚠️ **只能以手记为准，无源书背书** |
| ⭐⭐ **D 类：第三本书承载**（2026-10-14 新增）| ⚠️ **不在 A/B/C 任何一类**：<br>某书 X 里 0 命中、书 Y 里也 0 命中，<br>但作者**自己指明**它在**第三本书 Z** 里 |⭐ **作者在文中明确给出书名** |⭐ **以作者指明的 Z 书为准**，<br>⚠️ **不得判为 C 类自创** |

> ⭐⭐ **关键**：B 类与 C 类的分界线只有一条——**去源书全文检索一次**。
>
> ⭐⭐⭐ **D 类是本次新发现的漏洞（2026-10-14）**：
> ⭐ **「在某两本书检索不到」≠「作者自创」**。
> ⭐⭐ **黑马王子有四本书（《量柱擒涨停》《量线捉涨停》《伏击涨停》《涨停密码》），
> 只查前两本会误判。**
> 📌 **正确流程见第四节第4 步。**

## 二、⭐ 三次核实的真实结果（2026-10-14）

### 案例 1：平衡线 —— 章节号标错（A 类）

| | |
|---|---|
| 原标注 | 「理论出处：《量线捉涨停》**第 5 讲**（待编译）」 |
| 实际 | ⛔ 第 5 讲是「**谷底线**」；平衡线专讲是**第 8 讲** |
| 处理 | ✅ 已编译第 8 讲并补入正式定义，纠正标注 |

> 📌 **教训**：手记说「详见 X 书第 N 讲」时，**N 可能指目录序号也可能指页码**，
> 必须用**章节标题**复核，不能只看编号。

### ⭐⭐ 案例 2：涨停基因 —— 发现原书排印缺失（A 类 + 原书缺陷）

| | |
|---|---|
| 原标注 | 「理论出处：《量线捉涨停》（**待编译**，原文称已系统介绍）」 |
| 实际 | 源书**确有**六条基因清单（序言转述演讲），但 ⛔ **「基因之三」排印缺失** |
| 核查 | ① 全文检索「涨停基因之三」→ 0<br>② 查**原始 OCR 分片**→ 同样 0<br>③ 查正文第三章「伏击七则」编号连续无缺 |
| 结论 | ⭐ **不是本库漏编译，是原书序言本身缺号**（之二直接跳之四）|

> ⭐⭐ **本流程的关键一步：查原始分片**。
> 若只查合并后的全文，无法区分「OCR 丢字」与「原书缺字」。
> 📌 **这个区分很重要** —— 否则会误以为是自己没编译完，反复排期。

### ⭐⭐⭐ 案例 3：现场直憨 —— 自创词被误标为源书概念（C 类）

| | |
|---|---|
| 原标注 | 「理论出处：《量线捉涨停》（**待编译**，**原文多次引用**）」 |
| 实际 | ⛔⛔ **两本源书全文 0 命中**；手记（一）45 次、手记（三）65 次 |
| 结论 | ⭐ **纯手记自创词**，「原文多次引用」**不成立** |

> ⚠️⭐ **这三个案例合起来说明一件事**：
> **「待编译」这个状态被误用过多次**——
> 它既被用来表示「源书还没编译」，
> 也被用来表示「源书里根本没这内容」。
> ⚠️ **这两种情况必须分开标注**，否则会一直假性排期。

### ⭐⭐⭐⭐ 案例 4：凹底淘金 —— 「第三本书承载」，误判为 C 类（D 类，⭐⭐ 本库最重要的一次纠错）

| | |
|---|---|
| 检索结果 | ⛔《量柱擒涨停》**1 次**、《量线捉涨停》**1 次**（基本 0 命中）|
| 初判 | ⚠️ 按三分类会判为 **C 类·手记自创** |
| ⭐ **实际** | ⭐⭐⭐ **D 类：作者亲手指明在第三本书里** |

**作者原话（6~9册第21578 行，逐字）**：
> 「凹口淘金的位置高于凹底淘金，利润空间也大于凹底淘金，
> 所以，王子在《量柱擒涨停》和《量线捉涨停》里**只讲了凹口淘金，没有讲凹底淘金**。
> ⭐⭐ **清华大学出版社出版的《伏击涨停》和《涨停密码》书中，
> 讲解过凹口淘金与凹底淘金接力的案例**，
> 大家可以对照查看，体会二者的联系和区别。」

⭐⭐ **本库已实机验证该出处存在**（2026-10-14）：
> 《伏击涨停+涨停密码》全文：**凹底淘金 23 次**、凹口淘金 32 次 ✅
> 且找到**《涨停密码》原文**：
> 「《涨停密码》介绍的『**凹底淘金**』战法，**重在凹底**……
> 这只是解决了形态问题，**没有解决时机问题**。
> 什么状况下才能不失时机地参与……**『一剑封喉』**可以给我们很大的帮助。」

> ⭐⭐⭐ **本库评价：这是「作者指路 + 实机验证」的完整闭环**，
> ⭐⭐ **并且额外挖出一个新术语「一剑封喉」**（解决凹底淘金的时机问题）。
> 📌 若只查《量柱擒涨停》《量线捉涨停》两本，
> ⭐⭐ **就会把这个有正式出版出处的概念误判为「自创词」——
> 而本库曾据此写过结论。**

### ⭐ 案例 5：凹底 ≠ 凹口（同一组术语必须分开）

> 原书第 21451~21455 行给出界分：
> ⭐ **凹口淘金的位置高于凹底淘金，利润空间也大于凹底淘金。**
>
> | | 凹口淘金 | 凹底淘金 |
> |---|---|---|
> | 位置 | ⭐ 高 | ⭐ **低（波段谷底）** |
> | 利润空间 | ⭐ 大 | ⭐ **小** |
| 检索频次 | 量柱 35 / 量线 29（⭐ 正式内容）| 量柱 1 / 量线 1（⭐ 需另找出处）|

> ⭐⭐ **本库强调**：**两个术语名只差一字，但含义、位置、利润空间全不同。**
> ⚠️ **不可混用**——这是最容易出错的一组。

## 二之二、⭐⭐⭐ 【2026-10-14 严重警告】残缺全文文件陷阱

> ⭐⭐⭐ **本库素材层存在同名但内容残缺的「全文」文件，
> 若用它做溯源检索，会得到「全部 0 命中」的假结论。**

### 证据（实测）

| ⭐ **文件名** | ⭐ **体积** | ⭐ **检索「涨停」** | ⭐ 判定 |
|---|---|---|---|
| ⭐⭐ `量柱擒涨停-全文.txt` | ⭐ **6,604 字节** | ⭐ **0 次** | ⛔ **残缺占位** |
| ⭐⭐ `量线捉涨停-全文.txt` | ⭐ **7,961 字节** | ⭐ **0 次** | ⛔ **残缺占位** |
| ✅ `量柱擒涨停-OCR-简体.txt` | 476,218 字节 | ⭐ **正常命中** | ✅ **真本** |
| ✅ `量线捉涨停-OCR-简体.txt` | 540,975 字节 | ⭐ **正常命中** | ✅ **真本** |

> ⭐⭐⭐ **后果**：用 `-全文.txt` 检索 → 「凹底淘金」等术语全部 0 命中
> → ⭐⭐ **会被误判为「C 类手记自创词」**
> → ⚠️ **这正是本日案例 4 差点出错的原因之一。**

### ⭐ 铁律：溯源前必须先验文件

```bash
# ⭐⭐ 任何溯源检索之前，先确认文件是真的
ls -la <目标全文>.txt
grep -c "<该书的标志性高频词>" <目标全文>.txt
# ⭐ 文件明显偏小或标志性词0 命中 → ⛔ 换 -OCR-简体.txt
```

> ⭐⭐⭐ **本库的正确文件命名约定**：
> ⭐ **`-全文.txt`** = epub/epub直抽或完整OCR 合并
> ⭐ **`-OCR-简体.txt`** = PDF OCR 后繁转简
> ⚠️ ⭐ **但本库存在反例**，⭐⭐ **所以必须实测，不能靠文件名判断。**

## 三、⭐⭐ 核实流程（可复用）

```
拿到一个概念的「理论出处」标注后：

① 确认检索对象是【合并后全文】还是【原始分片】
② 在【两本源书】全文检索该术语（两种写法都试，OCR 常有讹字）
   │
   ├─ 命中 → A 类或 B 类
   │├─ A 类 → 定位专章/专节 → 补编译
   │        └─⚠️ 同时核对「章节号」是否对得上（案例 1）
   │        └─⚠️ 若清单式内容缺号 → 查原始分片（案例 2）
   └─ 0 命中 ⛔⛔ **不要立刻判C 类！先走第 ④ 步**（案例 4 的教训）
              ⭐ 改标注为「手记自创，无源书背书」
              ⭐ 不得写「待编译」

③ 无论哪类：⚠️ B 类须核对【原话】而非转述
   （已有先例：手记写「过线必用中到大阳」，
     源书原话是「冲线必有中到大阳」）

⭐⭐⭐ ④ ⭐⭐⭐ **【2026-10-14 新增，必做】检查「还有没有第三本书」**
   │
   ├─ ⭐⭐ 先在原文里搜「详见」「只讲了」「出版」「书名」
   │   （案例 4：作者亲口说「《伏击涨停》和《涨停密码》讲解过」）
   ├─ 若作者指明了书名 → ⭐⭐⭐ **去那本书全文检索**
   │   ├─ 命中 → ⭐⭐ **D 类·第三本书承载**（以该书为准）
   │   │        └─ ⭐ **并继续挖该书的补充内容**（案例 4 挖出「一剑封喉」）
   │   └─ 仍 0 命中 → ⛔ 记录「作者指路存疑」，⚠️ 不轻易判 C 类
   │
⭐⭐ └─ 作者未指路 → 才可判 ⭐ **C 类·手记自创**
```

## 四、⭐ 「待编译」标签的正确用法（本库约定）

| 情况 | ⭐ 正确标签 |
|---|---|
| 源书有该内容，尚未编译 | `待编译`（附章节号）|
| ⭐ **源书 0 命中** | ⛔ **不用「待编译」** → 改标「**手记自创 / 源书无此概念**」|
| ⭐ **原书排印缺失** | ⛔ 不用「待编译」 → 标「**原书缺失，已二次核对**」|
| ⭐ 内容属于别的库 | 标「**已分流**」+ 目标库（见 [[meta/素材分流判定]]）|

> ⭐⭐ **这条约定的价值**：
> 让「待编译」这个标签**重新变得可信**——
> 它只表示「真的还有活要干」，不表示「我还没查」。
