# OCR 与编译踩坑记录

> 本库所有"格式踩坑"的**唯一权威出处**。每条都是实测数据，不是经验之谈。

## 一、⭐⭐⭐ 伪文字层的三代判据（三次进化）

### 第一代：按抽样字数（❌ 已被推翻）

```
❌ 抽样每页 > 100 字 → 判为真文字层
```
⛔ **实测反例**：《股票魔法师》273 页，每页 122 字，**去广告后正文 0 字**。

---

### 第二代：按**正文行**占比（⚠️ 仍会漏判）

```
正文行占比 > 0.7 可用 / < 0.3 必须 OCR
```
⚠️ **实测反例**：《可转债投资黄金宝典》（阿秋）218 页 —— **正文 0 字**，
但每页有一行水印「公众号：财金视界」，按**行数**算 1:1 → **占比 0.50**，
被判成"✅ 真文字层"。

📌 **漏判的根因**：**行数占比会被水印稀释**。

---

### ⭐⭐⭐ 第三代：加**字数占比**（当前判据，已落地）

```python
# check_textlayer.py 当前实现
ratio      = real_lines / (real_lines + noise_lines)      # 行数占比
char_ratio = real_chars  / (real_chars  + noise_chars)    # ⭐ 字数占比

if real_lines == 0:      verdict = "伪文字层❌（全是广告，正文0字）"
elif char_ratio < 0.3:   verdict = "伪文字层❌（广告占字数主体）"     # ⭐ 新增
elif ratio < 0.3:        verdict = "伪文字层⚠️（正文占比低）"
elif ratio > 0.7 and char_ratio > 0.7: verdict = "真文字层✅"
else:                    verdict = "混合⚠️（含噪声，需清洗）"
```

### ⭐ 为什么字数占比才是硬指标

|场景 | 行数占比 | ⭐ **字数占比** |
|---|---|---|
| 每页 1 行水印（8 字）+ 正文 0 字 | **0.50** ❌ 误判 | **0.00** ✅ 正确 |
| 每页 1 行水印（8 字）+ 正文 2000 字 | 0.005❌ 误判低 | **0.996** ✅ 正确 |

📌 **水印是"短但密"，正文是"长但稀"** —— 只有字数能区分。

## 二、⭐ 同批次也要逐本检测

⚠️ **不能用"上一本能抽文字"推定"下一本也能"。**

**实测反例**（同一 Z-Library 源，页眉水印完全相同）：
| 书 | 判定 |
|---|---|
| 《投资小白躺赚指南》 | ✅ 真文字层（0.96）|
| 《可转债投资黄金宝典》 | ⛔ **伪文字层（0.00）** |

⭐ **结论**：**批次只影响水印来源，不影响内容类型**。

## 三、⭐ 格式成本排序（实测量化）

| 格式 | 相对成本 | 实测案例 |
|---|---|---|
| ⭐ **epub** | **秒级，0 OCR** | 《龙头价值与赛道》18万字；《魔法书》18.4万字/90节 |
| **PDF 真文字层** | **秒级，0 OCR** | 《躺赚指南》300页/10.3万字；《传奇投资人的智慧》694页/39万字 |
| **PDF 伪文字层** | **= 扫描版成本** | 阿秋218页需 OCR 约 30 分钟 |
| **PDF 扫描版** | **约 50 页/10 分钟** | 缠论593页=78分钟；高胜算360页=33分钟 |

📌 **结论：新书先看格式，epub/mobi > PDF。**

⚠️ **mobi 例外**：《攻守》mobi **不是 zip 结构**，zipfile 解析失败，
需专用工具（calibre / kindlegen）—— ⚠️ **不要直接当 zip 解**。

## 四、⚠️ OCR 的三个坑

| 坑 | 说明 |
|---|---|
| ⛔ **必须设环境变量** | `OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1`，否则 rapidocr 启动几秒就退|
| ⚠️ **大幅K 线图页会OOM** | 解法：降 dpi 链（160→130→100）+ 切 2/3 分图重试 |
| ⚠️ **后台进程会被回收** | ⚠️ **实测停在170页静默死亡**，需确认进程活着 |

### ⭐ 断点续传（必用）
```bash
python ocr_book.py "书名"           # 首次
python ocr_book.py "书名" 171 360   # ⭐ 从171页续传
```
📌 **分片存 `raw/distilled/shards_书名/`，可随时续跑。**

## 五、⚠️ Windows 中文路径坑

| 操作 | 坑 | 解法 |
|---|---|---|
| `rm -rf` | 回收站在中文路径**报错** | 已入库用 `git rm`；小文件用 `python os.remove()` |
| 批量替换 | 漏掉 `os.path.join(ROOT, ".raw", ...)` 这类拼接 | ⭐ **替换后必须 grep 复查残留** |
| python 路径含空格 | 后台任务漏空格会**静默失败** | 用全路径 `"E:/Work Buddy/runtimes/python-envs/default/Scripts/python.exe"` |

## 六、⚠️ 编译后必须回改 sources 页状态

**同一个坑我踩过两次**：

| 书 | sources 页写的 | 实际 |
|---|---|---|
| 《量线捉涨停》 | ✅ 正确 | ✅ |
| ⛔ **《黑马王子系列》** | 「**未开始**」 | **已有 6 个概念页** + manifest `compiled=True` |

📌 **后果**：lint 会把已完成的书报成"待编译"，浪费排查时间。
⭐ **检查方法**：`grep '^status:' wiki/sources/*.md` vs `manifest.compiled`

## 七、⚠️ 检测工具会误报（本库实测三次）

| 工具 | 误报类型 | 修法 |
|---|---|---|
| `lint_vault.py` | 扫 `raw/`素材层 → 28篇原始资料刷屏"孤立页" | `EXCLUDE_DIRS` 加 `raw` |
| `lint_vault.py` | `log.md` 里的 `[[...]]` 是**修复记录**不是链接 | 排除 `log.md`/`meta-lint/` |
| `check_growth.py` | 拿带路径的双链（entities/X 形式）比对裸页名 X → **24对全误判** | `links_of()` 去路径+去 `.md` |

⭐ **核心教训**：**写完检测工具必须先验证它会不会误报。**
📌 我曾差点照着误报去改 16 个页面。
