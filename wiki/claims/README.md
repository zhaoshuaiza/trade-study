# claims/ · 观点页

> 回答「**这话对不对、证据够不够**」。

---

## 放什么

**带判断的主张**——需要评估其正确性和证据强度的陈述。

| 例子 | 归属 |
|---|---|
| 「10% 止损优于 2N 止损」 | claims ✅ |
| 「趋势是价格高点低点依次抬升」 | concepts（中性描述） |
| 「均线多头排列胜率更高」 | claims ✅ |
| 「止损是硬约束」 | claims ✅（且是跨体系共识） |

## 判断标准

> **这话对错有争议吗？** 有争议、需要判断 → claims

---

## 与 concepts 的区别

```
concepts/  中性解释：这个概念是什么
claims/    带判断：有人说X，我认为对错是……
```

**例**：
- `concepts/中枢.md` → 「某级别走势类型重叠的价格区间」 ← 中性
- `claims/观点-中枢突破胜率更高.md` → 「突破中枢后的入场胜率显著高于其他时机」 ← 判断

---

## 必须标注可验证性

每条主张必须标 `verifiable`：

| 值 | 含义 |
|---|---|
| `verified` | 有数据/实证支撑 |
| `partial` | 有支撑但不完整 |
| `uncertain` | 间接证据，**不要当定论用** |
| `unknown` | 无法判断 |

> 📌 **诚实标注不确定，是这套库最值钱的地方。**
> 宁可在 claims 页写「这条我不敢确定」，也不要编一个确定的答案。
> 交易领域尤其如此——**错误的方法比不知道更危险**。

---

## 冲突怎么处理

两条 claims 结论不一致时（见 `CLAUDE.md` 4.3）：

1. **不覆盖旧结论**
2. 保留来源、适用对象、时间
3. 在 [`../comparisons/`](../comparisons/) 建冲突裁决页
4. **取舍由用户拍板**

> 多数「冲突」不是矛盾，是**适用对象不同**。
> 海龟 2N 用于期货趋势跟踪，题材股用 10% 固定止损——
> 任务是写清「什么时候用哪套」，不是选边站。
