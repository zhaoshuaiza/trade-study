# strategies/ · 交易策略层

> 复盘策略的沉淀层：把知识库判据落成**可统计的观测策略**，用每个交易日的真实行情检验它。
> 📊 数据性质：**历史事实统计**（信号→次日表现），不是回测、不是模拟盘、不是实盘收益。

## 这个目录放什么

| 文件 | 内容 | 维护方式 |
|---|---|---|
| [[策略总览]] | 策略索引 + 实盘检查顺序 + 已知边界 | 手工维护（稳定） |
| [[S1-主线首板跟随]] | 策略卡：依据/触发/胜定义/战绩/失效模式 | 手工维护，战绩数字引用 [[周度统计]] |
| [[S2-主线连板梯队]] | 策略卡（⚠️ 首周负期望，负面清单成员） | 同上 |
| [[S3-高位分歧回避]] | 策略卡（回避型，真龙例外必须复核） | 同上 |
| [[周度统计]] | 信号→次日表现全量统计 | **`strategy_engine.py weekly` 自动生成** |

## 三层数据流

```
raw/market/.manifest.json ──→ review.db ──→ signals.csv（信号登记簿）
                                              │
                              strategy_engine.py weekly
                                              │
                                      周度统计.md（本目录）
```

## 怎么用（实盘向）

1. **看总览**：[[策略总览]] 有五步固定检查顺序（阶段→题材→策略→强赎→离场）
2. **看战绩**：[[周度统计]] 的汇总表 + 明细表，每条信号都能追溯到具体日期与个股
3. **判断可信度**：先看「已验证」样本量（首周 S1=30/S2=9/S3=14），**样本 <30 的策略结论只作方向参考**
4. **手动更新**：不满一周也能统计——
   ```bash
   python strategy_engine.py weekly --from 20261019 --to 20261023
   ```
   手工补历史信号：编辑 `E:/股票/复盘数据/signals.csv` 增补行（source=manual），再跑 weekly 自动补算

## 红线（与 CLAUDE.md 4.4/4.5 一致）

- ⛔ 本目录**不产出新判据**——策略只是既有判据的应用组合，自定义阈值必须显式标注
- ⛔ 胜率数字**不得**当作有效性证据对外引用——没有对照组、样本极小、期间相关性强
- ⛔ 个股仅作统计样本出现，**不得当作选股结果**
- ⛔ 与走势无关的外生条款（转债强赎）优先于本目录一切策略信号
