# market · 行情实证（第九类页面）

> 本目录是**知识库与每日行情的联结点**。
> 上游是判据（concepts / syntheses），下游是每日真实行情。
> 一条闭环：**判据 → 每日验证 → 策略统计 → 反哺判据页修订**。

---

## 一、这个目录解决什么问题

原有的八类页面全是**从书里编译出来的静态方法论**。
方法论对不对、什么时候失效，只能靠记忆，没有一条**每日都被真实行情检验**的通道。

本目录补上这一环，并落成**三层结构**：

```
raw/market/.manifest.json ── 复盘原始数据索引（只索引不复制，MD5 防漂移）
        │
        ▼
  review.db（SQLite 聚合层，删了可重建）
        │
        ▼
  sync_review.py 每交易日跑一次
        │
        ├─→ market/YYYY-MM-DD.md ──────── 数据日页（纯数据快照）
        ├─→ market/reports/YYYY-MM-DD.md ─ 日报（实战检验：数据+K线结构+当日信号）
        ▼
  strategy_engine.py 登记信号 → 补算次日表现
        │
        ├─→ market/reports/weekly/YYYY-Www.md ── 周报（策略表现+判据观察+修订建议）
        ├─→ market/reports/monthly/YYYY-MM.md ── 月报（跨周趋势+判据仲裁）
        ├─→ market/strategies/周度统计.md ────── 机械统计（与周报同口径）
        └─→ market/strategies/S1~S3 卡「累计战绩」区自动刷新
        │
        ▼
market/判据实证台账.md（判据 × 日期 验证矩阵）
        │
        ▼
  回写：claims/（判据是否被观测支持）、syntheses/（阶段判读表修订）
  闭环自检：market/闭环检查清单.md（11 个环节逐项核对）
```

| 层 | 目录 | 放什么 |
|---|---|---|
| 原始数据 | `raw/market/`（[README](../market/../../raw/market/_README.md)） | xlsx 路径/MD5/行数索引，**不复制数据** |
| 复盘报告 | `market/reports/`（[README](reports/_README.md)） | 日报每交易日一份；周报 `weekly/`；月报 `monthly/` |
| 复盘策略 | `market/strategies/`（[README](strategies/_README.md)） | 策略卡（战绩自动刷新）+ 周度统计 |

## 三、判据 ID 体系（联动的主键）

判据 ID 全部取自 [[concepts/股市极客思考录·题材与热点判据]] 等原始判据页，
**本目录不新增判据，只做验证**。

| ID | 判据 | 可否机械验证 |
|---|---|---|
| HOT-2 | 热点至少持续三天才值得参与 | ✅ 题材连续出现天数 |
| HOT-5 | 热点退潮的两种形态 | ✅ 主线涨停数连续递减 |
| TOP-2 | 最题材启动时挤占其他题材资金 | ⚠️ 占比阈值**自定义**（原书无界线）|
| TOP-4 | 有妖股诞生的题材最有可能是最题材 | ✅ 最高板数，事实复核 |
| TOP-5 | 最题材必须有游资广泛参与 | ⚠️ 上榜家数占比 30% 线**自定义**（原文只说"可从交易所公开信息查询"，未给门槛）|
| SIZE-1 | 新闻刺激=小热点 / 政策刺激=大热点 | ⚠️ 关键词启发式，需人工 |
| SIZE-4 | 小盘股热点容易持续 | ❌ 只登记观测值，原书无界线 |

**TOP-5 的数据源**：akshare `stock_lhb_detail_em`（东方财富龙虎榜明细），
日页第七节给出主线题材的上榜家数占比、净买额及占全市场比重。
另含「上榜后 N 日涨跌幅」——**这是历史事实统计，不是策略回测**。

## 四、⛔ 三条不可违反的边界

1. **不是荐股单**（规则 4.5）。个股只作为判据验证的**样本**出现，
   每页显式标注。不得把本目录当选股输出用。
2. **不是回测**（规则 4.4）。全部产出是**市场观测**（涨停池快照），
   没有对照组、没有次日收益。台账页有专门一节写「本台账不能说明什么」。
3. **不自定阈值冒充原书判据**（规则 4.1）。TOP-2 的 30%、SIZE-4 的中位数，
   凡原书未给量化界线的，页面必须标 `自定义阈值` 或 `仅观测不下结论`。

## 五、日常怎么用

```bash
cd E:/股票/复盘数据
python sync_review.py          # 增量：只处理未入库的新日期（日页+日报+信号+checks.json）
python sync_review.py --all    # 重建全部
python sync_review.py --check  # 只预演不写盘

python strategy_engine.py weekly                          # 刷新周度统计（默认近5个交易日）
python strategy_engine.py weekly --from 20261019 --to 20261023   # 手动指定区间（不满一周也能统计）
python strategy_engine.py report-weekly                   # 生成周报 → reports/weekly/
python strategy_engine.py report-monthly                  # 生成月报 → reports/monthly/
python strategy_engine.py update-cards                    # 刷新策略卡/总览的累计战绩
python strategy_engine.py cumulative                      # 控制台看全区间累计战绩
python strategy_engine.py list                            # 查看信号登记簿
```

脚本位置：`E:/股票/复盘数据/`（`sync_review.py` 主流程、`strategy_engine.py` 策略引擎、
`ak_market.py` 网络取数、`review_db.py` 聚合层、`analyze_struct.py` K 线结构）
原始数据只索引不复制：`raw/market/.manifest.json`（含每个 xlsx 的 MD5 与行数）

**看盘时的入口顺序**（符合 CLAUDE.md 检索顺序）：

1. `wiki/hot.md` → 最近一次联动的结论
2. `market/strategies/策略总览.md` → 实盘五步检查顺序（阶段→题材→策略→强赎→离场）
3. `market/strategies/周度统计.md` → 各策略当前胜率与样本量
4. `market/判据实证台账.md` → 今天该听哪条判据、哪条已被观测否证
5. `market/市场结构时序.md` → 当前处于哪个阶段（冰点/修复/扩散/退潮）
6. 回判据页 → 具体怎么执行

**每周一次的自检入口**：`market/闭环检查清单.md`——11 个环节逐个核对闭环状态。

## 六、两个口径纪律（曾开板 ≠ 炸板；龙虎榜去重）

1. **曾开板 ≠ 炸板**。曾开板 = 盘中打开又封回（收盘仍在涨停池，即东财表「开板」列）；
   **炸板 = 收盘未封住（根本不在池内）**。判读资金强弱必须用**真炸板率** =
   炸板 /(涨停 + 炸板)，不能用池内曾开板率冒充。同花顺客户端顶部「炸板」计数、
   akshare 炸板池，都是这个口径。
2. **龙虎榜净买额按代码去重取最大值**。同一股票可因多个上榜原因产生多条记录，
   直接 sum 会重复计数。

## 七、已知局限

- K 线数据源：**方正证券小方 vipdoc**（10/23 起为最新源，日更）+ 通达信 new_tdx（滞后兜底）。
  结构分析（曹氏均线/缠论简化/一字板检测）已集成进每日报告第五节，
  但缠论**未做背驰与级别递归**，一字板会扭曲分型/中枢
- akshare 走东财/同花顺公开接口，**须盘后运行**（盘中可能取到延迟数据），
  页面标注取数时点；取数缓存 `E:/股票/复盘数据/_ak_cache/`
- 题材分类以数据源 `涨停原因` 字段为准，**不做过名称归一化**
- 晋级率只统计「前一日涨停 → 当日仍涨停」，不含断板后重新涨停
- 策略统计为**历史事实统计**：未计成本与可成交性，样本集中在同一段主线周期内，
  **期间相关性极强，不可外推**；自定义阈值（主线≥3日、分歧 3 次/25%/20%）必须随数字一起引用
